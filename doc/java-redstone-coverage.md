# Java 1.20.1 红石兼容矩阵

[文档索引](README.md) · [长期目标与达成情况](java-redstone-goal.md) · [行为规格](java-redstone-model.md) · [参考实验](java-redstone-verification.md)

## 状态口径

- **Implemented** 表示 RustCraft 具备该项具体行为。标为“原型”时注明限制。
- **Tested** 表示 RustCraft 有记录的回归覆盖，测试只证明该列所列范围。
- **Verified Compatible** 表示有指定版本的原版证据和同装置差分结果。数据报告、原版单侧实验或 RustCraft 单侧测试各自不足以获得这一状态。
- **TBD** 表示行为细节、实现或证据待补齐。下方的 P0–P2 表示红石专项优先级。

长期目标的总体达成情况见[红石长期目标与达成情况](java-redstone-goal.md)：P0 核心元件已有实现和选定原版差分，P1 未开始，P2 仅局部完成，最终验收尚未达成。

## 当前原版证据

GameTest 使用 Java Edition 1.20.1、Java 17、种子 0 和唯一的 `vanilla` 数据包。朝东普通活塞在直接通知后的首个 GT 伸出。QC 源单独放置和移除后各观察 5 GT，分别保持缩回和伸出。通过添加或移除下方相邻玻璃触发重新检查。伸出执行后的前两个 GT 看到移动占位，第三个采样刻看到稳定活塞头。

基础活塞的 BUD-008 中，单独的 Shape Update 未入队，来自同一侧的 NC 入队一个伸出事件。BUD-009 在同一 GT 内依次供电、撤源、再供电和通知，队列中保留一个伸出事件，下一 GT 伸出。BUD-010 发出通知后在同一 GT 撤源，伸出事件仍保留到后续 GT，但处理后未伸出。样本覆盖该方向与装置的队列及可见状态。完整内部调用次序、其他方向、其他设备及加载状态仍需单独验证。
